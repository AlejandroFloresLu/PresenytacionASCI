01Depuración de nomenclatura en requerimientos funcionales

MedioAprobado · Buenas prácticas IEEE 830 / ISO/IEC/IEEE 29148

Justificación. Sustituir frases de navegación como «Ingreso a gestión de…» por verbos de proceso de negocio. Bajo IEEE 830 un requerimiento especifica una funcionalidad transaccional (alta, baja, modificación, consulta, validación), no el acceso a una pantalla.

Estrategia. RF-01 «Administración y control de usuarios» · RF-02 «Gestión sociodemográfica de adolescentes» · RF-03 «Gestión procesal de expedientes judiciales» · RF-05 «Gestión de catálogo de medidas socioeducativas».

02Roles/perfiles antes que usuarios (RF-12 y RF-01)

MedioAprobado · Integridad de dominio y datos

Justificación. En seguridad.prsn la vinculación a un perfil/cargo (tppr_id) es una clave foránea: un usuario no puede existir sin un perfil asignable. Definir usuarios antes que perfiles altera el orden de seeders, migraciones y formularios.

Estrategia. Reordenar casos de uso y seeders: primero parametrizar el catálogo de cargos/roles; luego el alta de cuentas vinculadas a un rol existente.

03Jerarquía de perfiles en seguridad.prfl

BajoAprobado · Simplificación de entidades ORM

Justificación. El catálogo de 7 perfiles del SNAI es lineal. Forzar @TreeParent()/@TreeChildren() sobrecarga las consultas con CTE recursivos innecesarios; prflpdre se mantiene como entero nullable.

Estrategia. Mapear la columna como atributo simple en PerfilEntity.

@Column({ name: 'prflpdre', type: 'int4', nullable: true })
perfilPadreId: number | null;

04Articulación activa de prfl, accn, prms y sesn

AltoAlineado con la directriz: no se borra ninguna tabla

Justificación. El diseño original concibió una matriz RBAC granular en base de datos. Si el backend sólo valida en código, estas tablas quedan desconectadas; deben aprovecharse para autorización dinámica y auditoría de sesiones.

Estrategia. Sesión: en AuthService, tras emitir el JWT, insertar en sesn (sesnfcin = NOW()); en logout, sesnfcfn = NOW(). Permisos: un PermissionsGuard que verifique la acción autorizada en prms.

05Auditoría transaccional centralizada en PostgreSQL

AltoAlineado con la directriz: los logs van dentro de la base

Justificación. El trigger fn_registrar_historial() lee app.usuario_id. Si el backend no lo inyecta en cada escritura, se registra COALESCE(v_usuario_id, 0) como usuario cero y se pierde la trazabilidad exigida por el SNAI.

Estrategia. Inyectar la variable de sesión en cada transacción con QueryRunner de TypeORM.

await queryRunner.query(`SET LOCAL app.usuario_id = '${usuarioId}'`);
// Ejecutar INSERT / UPDATE / DELETE

06Corrección semántica en el diagrama de nivel 0

BajoAprobado · Rigor en análisis y diseño

Justificación. Los flujos de actores operativos hacia el sistema son entradas (inputs), no «Reportes». Un reporte es una salida analítica consolidada (RF-16).

Estrategia. Flechas entrantes: registro de adolescente, ingreso de expedientes, asistencia a talleres. Flechas salientes: reportes estadísticos, matrices de cumplimiento de medidas, expedientes consolidados.

07Mapeo ORM entre base de datos y backend NestJS

MedioAprobado · Coherencia de código y respeto al DDL físico

Justificación. El DDL usa nombres abreviados (prsn, prsnnmbr, tppr_id) y el backend conceptos de dominio (User, /api/v1/users). La discrepancia se resuelve en los decoradores, sin renombrar tablas.

Estrategia. Configurar el mapeo explícito en las entidades TypeORM.

@Entity({ name: 'prsn', schema: 'seguridad' })
export class UsuarioEntity {
  @PrimaryGeneratedColumn({ name: 'prsn_id' }) id: number;
  @Column({ name: 'prsnnmbr', length: 31 }) nombre: string;
  @Column({ name: 'prsnapll', length: 31 }) apellido: string;
  @Column({ name: 'prsnmail', length: 63 }) email: string;
  @Column({ name: 'prsnpass', length: 63, select: false }) password: string;
}

08Tabla detalle medida_expediente con orden obligatorio

CríticoMandatorio por normativa legal (CONA)

Justificación. Según el CONA (Art. 369, 370 y 378) los jueces pueden imponer medidas socioeducativas simultáneas o sucesivas. orden tipifica la precedencia (medida 1, 2, 3…), y las fechas y el estado de cumplimiento pertenecen a cada medida, no al expediente.

Estrategia. Crear la tabla en el esquema adolescente, con índices y triggers, y retirar mdso_id directo de expediente.

CREATE TABLE adolescente.medida_expediente (
  mdex_id SERIAL PRIMARY KEY,
  expe_id INT4 NOT NULL,
  mdso_id INT4 NOT NULL,
  orden INT4 NOT NULL,
  fecha_inicio DATE NOT NULL,
  fecha_fin DATE,
  estado_cumplimiento VARCHAR(50) NOT NULL DEFAULT 'En proceso',
  estado CHAR(1) NOT NULL DEFAULT 'V',
  CONSTRAINT chk_mdex_orden CHECK (orden > 0),
  CONSTRAINT chk_mdex_fechas CHECK (fecha_fin IS NULL OR fecha_fin >= fecha_inicio)
);

09Preservación del campo cedula (cédula o pasaporte)

MedioAprobado · Alineado con la directriz del docente

Justificación. VARCHAR(20) cubre los 10 dígitos de la cédula ecuatoriana y los pasaportes alfanuméricos (6–12 caracteres) sin tablas accesorias: menos joins y compatibilidad total.

Estrategia. Flexibilizar la validación en CreateAdolescenteDto.

@IsNotEmpty({ message: 'El documento de identificación (cédula o pasaporte) es obligatorio' })
@IsString()
@Length(3, 20)
@Matches(/^[a-zA-Z0-9]+$/)
cedula: string;

10Atributo estado en todas las tablas

AltoAprobado · Requerimiento institucional y borrado lógico

Justificación. Los expedientes judiciales juveniles no deben eliminarse físicamente por auditoría y archivo legal. El estándar 'V'/'F' permite que el transformador BooleanVF opere igual en todos los módulos.

Estrategia. Agregar la columna a todas las tablas que no la tenían.

ALTER TABLE adolescente.adolescente
  ADD COLUMN IF NOT EXISTS estado CHAR(1) NOT NULL DEFAULT 'V'
  CHECK (estado IN ('V', 'F'));

11Dimensionamiento de tipos de datos en DDL y DTOs

MedioAprobado · Integridad y consistencia

Justificación. prsnpass VARCHAR(63) aloja con holgura los hashes bcrypt de 60 caracteres. Normalizar VARCHAR con longitud definida frente a TEXT optimiza memoria.

Estrategia. Validar en el DTO de creación de usuario que la contraseña tenga entre 8 y 63 caracteres antes del cifrado.

12Identificadores entre comillas ("fcCrea", "fcMod")

BajoAprobado · Mantenibilidad ORM

Justificación. PostgreSQL convierte identificadores a minúsculas salvo que vayan entre comillas dobles; TypeORM puede fallar si no se preserva el nombre exacto.

Estrategia. Mapear explícitamente las columnas de auditoría en todas las entidades.

@CreateDateColumn({ name: 'fcCrea', type: 'timestamp' }) fechaCreacion: Date;
@UpdateDateColumn({ name: 'fcMod', type: 'timestamp' }) fechaModificacion: Date;
